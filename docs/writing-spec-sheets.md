# Writing Spec Sheets
- **Goal** Write an implementation guide for future LLMs
- **Scope** Only describe what needs to change. Stick to what is relevant for future LLMs.

# Updating Spec Sheets
- **When to update:** If the spec hasn't been fully implemented at the end of your turn, 
  update the spec sheet. Otherwise ignore it. See details below.
- **Describe the current state.** A spec describes what the system is and what's left to
  build — not the bugs found and fixed along the way, or stats that were true once. If a
  sentence is only included because something used to be broken, cut it.
- **Don't narrate corrections.** Skip "not X, but Y" sentence constructions and 
  references to how things were debugged.
